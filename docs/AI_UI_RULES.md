# AI UI Implementation Rules

When you change the Career Companion frontend as an AI coding agent, you **must** follow these rules. They come from design part 1, which the owner approved on 17 Oct 2026, and design part 2, approved on 22 Oct 2026. The base is IBM Carbon with a Render-style look; [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md) has the themes, type, the app shell, motion and the list of shared parts.

## Do this

1. **Read first.** Read `DESIGN_SYSTEM.md` and the shared parts in `src/components/ui/` before you change a screen.
2. **Reuse the shared parts.** A list is a `DataTable`; a dropdown is `Select` or `Combobox`; a "…" menu is `OverflowMenu`; a notice is `InlineNotification`; a failed part is `SectionError`; a confirmation is a toast. If a part is missing, add a reusable one to `src/components/ui/` (on `@base-ui/react`), not a one-off in a page.
3. **Use tokens only.** Colours, layers and borders come from the tokens in `src/index.css` (`bg-surface`, `text-text-secondary`, `border-border-subtle`). No hex values and no raw Tailwind colours.
4. **One main button.** One primary button per page or panel (the accent pill: dark in Light, light in Dark). Everything else is secondary, tertiary, ghost or in a "…" menu. Danger actions sit last in the menu, in red, and ask before they act.
5. **Colour means something.** Colour only in status rings, red for past due (`text-late`) and green switches (owner, 18 Nov 2026; no blue since 21 Nov 2026). The new-mail dot is the accent. A status is one small ring (`Ring`, `StatusRing`, `StatusBadge` in `ui/ring.tsx`), with its kind from `src/lib/statusTags.ts` only, on phones and laptops. One accent (`--accent`, the text colour; no blue). The same thing looks the same everywhere.
6. **Human words.** On screen, never system words such as "Email Processed", "PENDING", "COMPLETED" or "RELEVANT", and never a raw server error. Labels, states and dates are tested functions in `src/lib/`. Sentence case.
7. **Every state.** Loading shows a skeleton; empty says why and offers the next step; an error says what failed in plain words and offers "Try again". One failed part never hides the rest of the page.
8. **Safe saves.** A save that may or may not have happened is read back from the server and never sent again by itself. Saves use the revision the page shows, so a change made elsewhere is never overwritten.
9. **Lists keep their place.** Search, filters, sort and page live in the URL, so a reload, Back and the breadcrumb return to the same view.
10. **Phones.** Follow "Phones" in DESIGN_SYSTEM.md, which follows the Linear iOS app: no sideways scroll at 375px, the phone frame (`PhoneShell`: the icon-only glass tab bar with its Search circle, round glass buttons and capsules, big titles with `PhoneTitle`, `size="bar"` on setup pages), plain rows (`PlainSection`, `PlainRow`, `PlainLinkRow`; `DataTable phonePlain`), the `text-phone-*` sizes, floating sheets for every choice and tall sheets for writing, and a bottom bar on detail pages (`PhoneBottomBar` with `BarCircle`, `BarField`, `BarCircle`). Mails start with the person, applications with the company; a detail page has a grey line, a big bold title and its facts as pills in one round card. A page puts its top buttons in with `TopBarActions`. Draw phone-only parts with `useIsPhone`, never twice with CSS hiding one, so each name is in the page once.
11. **Accessibility.** Visible focus on every control; an `aria-label` on every icon-only button; every field has a label; check the contrast of new colours; check that Base UI parts are wired correctly (labels, names), do not assume it.
12. **Smooth size changes.** A section the user shows and hides is a `Collapse`, never `{open && …}`. Something that appears by itself (a field error, a notice) is wrapped in `Reveal`; `InlineNotification` already is. A dialog body and the Combobox list already sit in `AutoHeight`; put other boxes whose content jumps in one too.
13. **Offline.** Every change goes through the API client, which refuses it offline (`kind: 'offline'`) before anything is sent, and the offline toast says so. A part that shows its own failure message leaves `isOfflineError` errors to that toast; a change made without `useMutation` shows `OFFLINE_CHANGE` itself. Never hold a change to send later. Data a page needs offline is on the kept list in `lib/offlineCopy.ts`; a new page that should open offline adds its query keys there.
14. **Laptops.** Follow "Laptops" in DESIGN_SYSTEM.md: small changes only. Keep the layout, side menu, tables and pages; use the same rings, glass menus and plain words as the phone.

## Not allowed

- A sparkle icon for AI, and icons from any set but Lucide (`lucide-react`; the AI is `AiIcon`, the machine-learning model shape drawn thin).
- A grey page to set parts apart. Cards are panels (`panel`: soft grey, 16px corners, no line); mails in a conversation stay white with a line.
- Em dashes in on-screen text.
- A coloured status tag, rounded grey groups or icon squares on a phone page, a solid phone top bar, the old four-button action bar (`ActionBar`) on a detail page, and a slide between laptop pages (owner, 18 Nov 2026).
- Shadows and frosted glass anywhere but on things that float (menus, dropdowns, dialogs and sheets, toasts, the phone's bars, round buttons and capsules, the Install card), the faint shadow under buttons, and in Dark the raised page sheet and the open menu item. Glass is quiet: no shine, no glow. Square corners on a shared part: use the corner sizes in DESIGN_SYSTEM.md.
- Uppercase text, and mono text anywhere but code, tokens and the count after a table's first header label.
- `className="mb-0"` on `PageHeader` inside a `space-y-*` parent: Tailwind 4 lets it remove the gap under the header.
- Font sizes outside the scale in DESIGN_SYSTEM.md, and extra letter spacing (Carbon's 0.16px and 0.32px are gone with IBM Plex).
- Animation on hover only, endless animation, and motion longer than 450ms. Motion uses Carbon times (70 to 400ms) and curves in CSS; menus and toasts use the spring curve (`ease-spring`), phone sheets settle with `ease-settle` and the tab bar becomes the bottom bar with `ease-morph` (owner, 18 Nov 2026), and phone page slides use the small spring in `lib/spring.ts`. All of it turns off (or becomes a short fade) when the device asks for reduced motion. `AutoHeight` must measure its content, so it uses the browser's own animation API. No animation library.
- A transition that lists only `transform` for Tailwind's `translate-*`, `scale-*` or `rotate-*` classes. Tailwind 4 sets the `translate`, `scale` and `rotate` properties, so list those (or use `transition-transform`), or the movement snaps.
- A PWA plugin, or a service worker that keeps `index.html` for use while online, `version.json`, or any API answer. `public/sw.js` takes the page from the network while online (the kept copy is only for offline) and keeps the build's hashed files; the data copies are the app's own (`lib/offlineCopy.ts`). Anything more would fight the quiet update or show old data as new.
- "Loading…" text where a skeleton fits.
- The browser's own `<select>`.
- A new page or dialog pattern that differs from the existing ones without the owner's OK.
- PR titles, PR descriptions, branch names and commit messages that name a parent issue (such as the design part 1 or design part 2 parent); name only the PR's own issue.
