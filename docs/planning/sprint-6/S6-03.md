# S6-03 — Implement robust concurrent AI processing logic and application matching

Status: proposed local ticket.

## 1. Goal
Fix massive concurrency bugs in the `emailProcessingJob.ts` worker and ensure `matcher.ts` behaves correctly under concurrent load.

## 2. Problem / Gap
`emailProcessingJob.ts` only processes `jobs[0]` from the array passed by `queue.work`, silently dropping all other jobs in a batch while marking them as successful. This causes silent email processing failures.

## 3. Proposed Implementation
1. Fix `emailProcessingJob.ts` to iterate over all `jobs` in the array and process each one, or configure pg-boss to truly deliver single jobs if batching is not intended.
2. Review `matcher.ts` to ensure its read-then-lock patterns are safe from race conditions when two emails for the same ambiguous application are processed exactly simultaneously.

## 4. Acceptance Criteria
- All jobs handed to the `EMAIL_PROCESSING_JOB` worker are processed.
- No emails are silently dropped during concurrent ingestion spikes.
