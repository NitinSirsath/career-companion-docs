# S6-01 — Establish application status semantics and manual user correction

Status: proposed local ticket.

## 1. Goal
Unify effective application status across API and UI, and add a concurrency-safe manual application status correction backend API.

## 2. Problem / Gap
Currently, status precedence is inconsistent between UI and API. Furthermore, there is no manual status correction endpoint, meaning AI choices cannot be overridden safely.

## 3. Proposed Implementation
1. Add `effectiveStatus`, `statusSource`, and `hasStatusConflict` to the GET Application responses based on `userStatus ?? aiStatus`.
2. Implement `PATCH /api/applications/:id/status` using an atomic DB transaction with `userStatusRevision` to prevent concurrent overwrite.

## 4. Acceptance Criteria
- `effectiveStatus` follows user-first precedence.
- PATCH endpoint supports atomic updates with revision checking (409 Conflict on stale revision).
- AI writes preserve manual fields.
